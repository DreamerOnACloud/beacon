## Further reading

- [Idempotent requests — Stripe API docs](https://docs.stripe.com/api/idempotent_requests) — the industry-standard pattern this post's demo is modeled on: an `Idempotency-Key` header that lets a retried request safely replay the original result instead of repeating the effect.
- [Idempotent — MDN Web Docs Glossary](https://developer.mozilla.org/en-US/docs/Glossary/Idempotent) — the concise, spec-level definition: why HTTP's GET/PUT/DELETE are idempotent by design and POST isn't.
- [Idempotence — Wikipedia](https://en.wikipedia.org/wiki/Idempotence) — the general mathematical root of the property (`f(f(x)) = f(x)`), if you want to see the API case as one instance of something broader.
