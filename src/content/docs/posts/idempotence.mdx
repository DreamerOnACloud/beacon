## The concept

{/* DRAFT, written by Claude. Review and edit before this counts as done;
per idea.md, whoever didn't draft it is the one who signs off. */}

That's one instance of a more general property. An operation is
**idempotent** if doing it many times has the same effect as doing it once.
Repetition doesn't add anything extra, and it doesn't cause harm: it just
confirms what was already true.

The clearest version of this is a small piece of math: a function `f` is
idempotent if `f(f(x)) = f(x)` for every `x`. A few everyday examples:

- **Absolute value.** `abs(abs(-5))` is `5`, the same as `abs(-5)`. Once a
  number is non-negative, taking the absolute value again changes nothing.
- **Rounding.** Rounding an already-rounded number gives back that same
  number. The second rounding has nothing left to do.
- **Sorting.** Sorting an already-sorted list produces the identical list.
  There's no "more sorted" to reach.

In each case, the first application moves something into a state, and every
application after that just re-confirms it's already there.

Software has the same property, just applied to actions instead of pure
functions: an operation is idempotent if performing it several times leaves
the system in the same state as performing it once. This matters most when
an action might accidentally happen more than once: a button clicked
twice, a request that times out and gets retried, a message that gets
redelivered, a release step in a pipeline getting re-run. If the underlying
operation is idempotent, none of that is dangerous. If it isn't, every
accidental repeat is a bug waiting to happen.

## Further reading

- [Idempotent requests (Stripe API docs)](https://docs.stripe.com/api/idempotent_requests): the industry-standard pattern this post's demo is modeled on: an `Idempotency-Key` header that lets a retried request safely replay the original result instead of repeating the effect.
- [Idempotent (MDN Web Docs Glossary)](https://developer.mozilla.org/en-US/docs/Glossary/Idempotent): the concise, spec-level definition: why HTTP's GET/PUT/DELETE are idempotent by design and POST isn't.
- [Idempotence (Wikipedia)](https://en.wikipedia.org/wiki/Idempotence): the general mathematical root of the property (`f(f(x)) = f(x)`), if you want to see the API case as one instance of something broader.
